# น้ำปิงที่สะพานนวรัฐ — เว็บพยากรณ์ระดับน้ำ P.1 (เวอร์ชันแรก)

เว็บแสดงระดับน้ำแม่น้ำปิงที่สถานี P.1 สะพานนวรัฐ เชียงใหม่ พร้อมพยากรณ์ล่วงหน้า 1, 3 และ 6 ชั่วโมง
และแนวโน้ม 12 ชั่วโมง ใช้โมเดลที่ชนะจากรายงานการทดลอง (ทำนาย "การเปลี่ยนแปลง" ของระดับน้ำ
ด้วย Ridge + Gradient Boosting แล้วเฉลี่ยกัน)

> ต้นแบบงานวิจัย ไม่ใช่ระบบเตือนภัยทางการ

## เริ่มใช้งานเร็วที่สุด (โหมดสาธิต ไม่ต้องต่อเน็ต)

ต้องมี Python 3.10 ขึ้นไป

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt

P1_DEMO=1 uvicorn app.main:app --port 8000
# Windows PowerShell:  $env:P1_DEMO="1"; uvicorn app.main:app --port 8000
```

เปิด http://localhost:8000 จะเห็นแถบ "โหมดสาธิต" ด้านบน ลากแถบเวลาหรือกด "เล่น"
เพื่อย้อนดูน้ำท่วมเชียงใหม่ ก.ย.–ต.ค. 2567 ด้วยข้อมูลจริง ลิงก์ตรงไปยังเวลาที่ต้องการได้ด้วย
`http://localhost:8000/?at=2024-10-05 02:00`

โมเดลโหมดสาธิตเทรนจากข้อมูลก่อน `P1_DEMO_NOW` (ค่าเริ่มต้น 3 ต.ค. 2567 07:00) เท่านั้น
ช่วงหลังจากนั้นจึงเป็นการทำนายข้อมูลที่โมเดลไม่เคยเห็น เหมือนชุดทดสอบ forward ในรายงาน

## ใช้งานจริง (ดึงข้อมูลจาก ThaiWater)

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

ครั้งแรกที่เปิด ระบบจะ

1. โหลดข้อมูลน้ำท่วมปี 2567 (ใน `data/seed/`) เข้าฐานข้อมูล
2. ดึงข้อมูลย้อนหลัง 1 ปีของ P.1, P.67 และ P.21 จาก ThaiWater (ใช้เวลาประมาณ 1–2 นาที)
3. เทรนโมเดล แล้วดึงค่าล่าสุดทุก 10 นาที และเทรนใหม่ทุก 24 ชั่วโมง

ระหว่างนั้นหน้าเว็บจะขึ้นว่ากำลังเตรียมโมเดล รอสักครู่แล้วรีเฟรช สถานะดูได้ที่ `/api/health`

ข้อมูลทุกค่าที่ดึงมาถูกเก็บใน `data/p1.sqlite3` ยิ่งเปิดทิ้งไว้นาน ข้อมูลเทรนยิ่งมาก

### ด้วย Docker

```bash
cp .env.example .env
docker compose up -d --build
```

## คำสั่งช่วยเหลือ

python -m app.cli info         # สรุปข้อมูลในฐานข้อมูลและโมเดล
```

```

เทรนและทำนายด้วย `app.model` โดยตรง บนข้อมูลจริงที่โมเดลไม่เคยเห็น (ก.ย. 2569, `data/backtest/`) และน้ำท่วม 2567
ต้องไม่แย่กว่า `data/backtest/results/baseline_summary.md` ทุกครั้งที่แก้โมเดล รายละเอียดและผลอยู่ใน `docs/experiment-findings.md`

## หน้าเว็บตอบอะไร

ส่วนบนสุดของหน้า (ไม่ต้องเลื่อนบนมือถือ) ตอบ 4 คำถาม
1. **ตอนนี้น้ำอยู่ระดับไหน** ไม้วัดแดง-ขาว ตัวเลขใหญ่ และสถานะ
2. **อีกไม่กี่ชั่วโมงจะเป็นอย่างไร** พยากรณ์ 6 ชม. พร้อมช่วง, เวลาที่อาจถึงเกณฑ์ถัดไป (ไม่เกิน 6 ชม.), แนวโน้ม 12 ชม.
3. **ควรทำอะไร** คำแนะนำทั่วไปตามสถานะ แก้ข้อความได้ที่ `static/i18n.json` (`advice.*`) ไม่ต้องแตะโค้ด
4. **ข้อมูลสดแค่ไหน** วัดเมื่อกี่นาทีที่แล้ว เตือนเมื่อเกิน 2 ชม. และกล่อง "ตัวเลขพยากรณ์เชื่อถือได้น้อยลง" พร้อมเหตุผล
   (น้ำอยู่นอกช่วงข้อมูลเทรน, สถานีต้นน้ำไม่มีค่าใหม่, ข้อมูลไม่สด)

ท้ายหน้ามีตารางพยากรณ์รายชั่วโมง 1–6 ชม. ของแต่ละโมเดล (M4 Ridge, M6 GBM, M7 ค่าเฉลี่ย) พร้อมช่วงและ RMSE
จากการทดสอบย้อนหลังของแต่ละช่อง สำหรับนักวิจัยหรือคนที่อยากดูละเอียด

## หน้ารอง

- `/accuracy.html` **ความแม่นย้อนหลัง** ทุกพยากรณ์ที่ออกจริงถูกบันทึกในตาราง `forecast_log` แล้วเทียบกับค่าจริงเมื่อมาถึง
  แสดงคลาดเคลื่อนเฉลี่ย 7/30 วันแยกตามระยะล่วงหน้าและโมเดล เทียบกับการทายว่าเท่าเดิมและผลทดสอบตอนเทรน พร้อมกราฟพยากรณ์เทียบจริง
  (โหมดสาธิตไม่มีการพยากรณ์สด จึงแสดงเฉพาะผลทดสอบตอนเทรน)
- `/data.html` **ข้อมูลสำหรับนักวิจัย** ดาวน์โหลด CSV รายชั่วโมงทุกสถานี (สูงสุด 366 วันต่อครั้ง), CSV บันทึกพยากรณ์ และคำอธิบาย JSON API
  เอกสาร OpenAPI ที่ `/docs`
- `/admin.html` **สถานะระบบ** ผลการดึงข้อมูล 24 ชม., จำนวน 429, backfill, การเทรน, อายุข้อมูลแต่ละสถานี และรายการปัญหาที่ควรดู
  (อ่านอย่างเดียว ไม่มีปุ่มสั่งงาน)

ผู้ใช้ตั้ง "ระดับน้ำของฉัน" ได้ (เก็บใน localStorage ของเครื่อง) หน้าเว็บจะแสดงเส้นบนไม้วัดและกราฟ และบอกเมื่อพยากรณ์เข้าใกล้

## ตั้งค่า

ดูทั้งหมดใน `.env.example` และ `app/config.py` ค่าที่ควรตรวจก่อนใช้งานจริงคือเกณฑ์ระดับน้ำ
(เฝ้าระวัง 3.10, วิกฤต 3.70, ล้นตลิ่ง 4.20 ม. ตามไม้วัด) เพราะหน่วยงานอาจปรับเกณฑ์

## โครงสร้าง

```
app/
  config.py      สถานี, datum, เกณฑ์, ค่าตั้งต้น
  thaiwater.py   ดึงและแปลงข้อมูล waterlevel_load (ค่าล่าสุด) และ waterlevel_graph (ย้อนหลัง 1 ปี)
  store.py       SQLite และการแปลงเป็นข้อมูลรายชั่วโมง
  features.py    features แบบเดียวกับในรายงาน
  model.py       เทรน Ridge-delta + GBM-delta, ช่วงความไม่แน่นอนจาก blocked CV, พยากรณ์
  collector.py   งานเบื้องหลัง: seed, backfill, ดึงทุก 10 นาที, เทรนใหม่
  forecast_logic.py  ตีความพยากรณ์: เวลาถึงเกณฑ์ถัดไป, ระดับน้ำของฉัน, สถานะคำแนะนำ, ความเชื่อถือได้
  forecast_log.py    บันทึกพยากรณ์ที่ออกจริง เติมค่าจริง และสรุปความแม่น
  data_api.py    API สำหรับนักวิจัย: สถานี, ข้อมูลรายชั่วโมง JSON/CSV, CSV บันทึกพยากรณ์
  main.py        FastAPI: /api/forecast, /api/health และหน้าเว็บ
  cli.py         คำสั่งช่วยเหลือ
static/          หน้าเว็บ (HTML/CSS/JS ล้วน ไม่มี build step)
  i18n.json      ข้อความทั้งหมดของหน้า รวมคำแนะนำตามสถานะ
  js/            ES modules: main, hero, gauge, chart, fresh, mylevel, upstream, modeltable, demo
tools/           สคริปต์ Playwright สำหรับทดสอบหน้าเว็บ
data/seed/       ข้อมูลรายชั่วโมงน้ำท่วมปี 2567 ของ 3 สถานี
```

## โมเดลทำงานอย่างไร

- ทำนาย "ระดับน้ำจะเปลี่ยนไปเท่าไร" ใน 1–6 และ 12 ชม. แล้วบวกกับระดับตอนนี้ (หน้าหลักแสดง 1, 3, 6 ชม. ตามรายงาน ส่วน 2, 4, 5 ชม. อยู่ในตารางท้ายหน้า)
- ใช้แนวโน้มของ P.1 และระดับน้ำเทียบตลิ่งของ P.67 (แม่น้ำปิง ต้นน้ำ ~6 ชม.) กับ P.21 (น้ำแม่ริม ~2–3 ชม.)
- ตัวเลขที่แสดง = ค่าเฉลี่ยของ Ridge กับ Gradient Boosting (M7) ส่วนการเตือนที่ 6 ชม. ใช้ Ridge (M4)
  เพราะในการทดลองเตือนได้เร็วกว่าและพลาดน้อยกว่า
- ช่วงที่น่าจะเป็นคือ 5–95% ของความคลาดเคลื่อนจากการทดสอบย้อนหลัง และกว้างอย่างน้อย ±RMSE
- 12 ชม. แสดงเป็นแนวโน้ม (ขึ้น ทรง ลง) เท่านั้น เพราะยังคลาดเคลื่อนเกิน 20 ซม.

## ข้อจำกัดที่รู้แล้ว

- ข้อมูลเทรนเริ่มต้นมีน้ำหลากใหญ่แค่ปี 2567 โมเดลจึงพลาดได้มากเมื่อน้ำขึ้นเร็วจากลำน้ำสาขา
  หรือเมื่อน้ำล้นตลิ่ง (ในการทดลองพลาดถึง 51 ซม. ที่ล่วงหน้า 6 ชม.)
- ยังไม่มีข้อมูลฝนและการระบายน้ำจากเขื่อนแม่งัด
- endpoint ของ ThaiWater ไม่ใช่ API ทางการ อาจเปลี่ยนรูปแบบหรือตอบ 429 ได้

## ขั้นต่อไปที่แนะนำ

1. ขอข้อมูลรายชั่วโมงหลายปีจากศูนย์อุทกวิทยาชลประทานภาคเหนือตอนบน แล้วนำเข้าด้วย `store.upsert`
2. เพิ่มฝนที่ตกจริงและพยากรณ์ฝน (Open-Meteo) เป็น feature
3. แปลงระดับน้ำเป็นปริมาณน้ำด้วย rating curve
4. ประเมินแบบ leave-one-event-out เมื่อมีน้ำหลากหลายลูก
